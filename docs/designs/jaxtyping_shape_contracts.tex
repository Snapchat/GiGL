\section*{The problem}
Python's \code{Tensor} annotation says nothing about dtype, rank, or how dimensions relate. In graph learning, a mismatched embedding width or malformed ID tensor may travel through several layers before failing. The eventual error is often far from the boundary that admitted the bad value.

Jaxtyping turns those assumptions into readable, runtime-checkable contracts:

\begin{snippet}
from jaxtyping import Float
from torch import Tensor

def decode(
    query: Float[Tensor, "queries embedding_dim"],
    candidate: Float[Tensor, "candidates embedding_dim"],
) -> Float[Tensor, "queries candidates"]: ...
\end{snippet}

The shared \code{embedding_dim} name requires both inputs to have the same final dimension. A test fails at \code{decode}, before an invalid tensor can propagate.

\callout{\pill{Core idea}\quad A shape contract records the stable interface: tensor kind, dtype family, rank, and meaningful relationships between axes.}

\section*{Contract vocabulary}
Axes are whitespace-separated. Reusing a name binds equal sizes within one checked call.

\section*{What contracts provide}
\begin{minipage}[t]{0.48\linewidth}
\pill{Benefits}
\begin{itemize}
  \item Express the boundary more precisely than \code{Tensor}.
  \item Validate dtype, rank, fixed axes, and named-axis equality.
  \item Make semantic coupling visible in code review.
  \item Fail close to the invalid call on exercised test paths.
\end{itemize}
\end{minipage}\hfill
\begin{minipage}[t]{0.48\linewidth}
\pill{Limits}
\begin{itemize}
  \item Validate only annotated boundaries reached by tests.
  \item Cannot model key-to-axis equality in dynamic keyed containers.
  \item Require accurate contracts; guessed semantics create false failures.
  \item Complement static typing rather than replace it.
\end{itemize}
\end{minipage}

\section*{How PR \#748 works}
Runtime checking is installed by GiGL's unit, integration, and end-to-end test launchers before test discovery. Annotated \code{gigl} and \code{examples} code is instrumented as it is imported.

\rule{0pt}{34pt}\textbf{1. Test launchers}\par{\small Install checking} &
{\Large\color{teal}$\rightarrow$} &
\rule{0pt}{34pt}\textbf{2. Import hook}\par{\small Instrument packages} &
{\Large\color{teal}$\rightarrow$} &
\rule{0pt}{34pt}\textbf{3. Contracted call}\par{\small Check inputs and returns}

An uncaught \code{jaxtyping.TypeCheckError} fails the test command. Production training and inference retain the annotations as documentation but do not install runtime checking, avoiding instrumentation overhead and import-order sensitivity.

\callout{\pill{Why Typeguard 2.x}\quad Jaxtyping documents this integration path. GiGL's adapter presents Typeguard with shape-bearing annotations only, avoiding runtime evaluation of static-only Protocol, TypeVar, and forward-reference annotations.}

\section*{Contract policy}
\begin{itemize}
  \item Annotate stable tensor boundaries: loader and sampler interfaces, public model \code{forward} and \code{decode} methods, loss interfaces, and result containers.
  \item Use exact dtypes only when the boundary guarantees them. Use \code{Float} when mixed precision is valid; use \code{Int64}, \code{Int32}, \code{Float32}, or \code{UInt8} for hard guarantees.
  \item Reuse axis names only when dimensions must match. Use \texttt{\_name} for an independent dimension, \texttt{\_} for an unknown dimension, and \texttt{\#name} when size 1 is valid for broadcasting.
  \item Leave internal tensor operations, low-level message passing, and dynamic PyG or TorchRec keyed containers uncontracted unless they expose a stable boundary.
  \item Prefer no annotation over a guessed rank, dtype, or axis meaning.
\end{itemize}
